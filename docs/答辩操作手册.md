# CampusReserve 答辩操作手册

本文按“课前准备 → 启动 → 功能演示 → 压测演示 → 收尾”的顺序编写。所有命令在 **Windows PowerShell** 中执行，工作目录为 `C:\Code\Python\CampusReserve`。

## 1. 答辩速查

| 用途 | 地址或命令 |
|---|---|
| 学生端、管理端 | <http://localhost:8080/> |
| Locust 压测控制台 | <http://localhost:8089/> |
| Prometheus | <http://localhost:9090/> |
| Grafana | <http://localhost:3000/> |
| API 文档 | <http://localhost:8000/docs> |
| 查看容器 | `docker compose ps -a` |
| 启动或更新 | `docker compose up -d --build` |
| 停止并保留数据 | `docker compose down` |

推荐现场顺序：**检查服务 → 学生预约 → 管理员查询 → Locust 指标 → 并发防超卖测试**。如果时间紧，优先展示学生预约和 Locust 页面。

## 2. 环境和配置

### 2.1 需要安装什么

1. Windows 上安装并启动 Docker Desktop，使用 Linux 容器模式。
2. 安装支持 PowerShell 的终端和浏览器。
3. 首次构建需要网络连接，以获取 Docker 镜像及 Python、Node 依赖。正常运行时不需要在 Windows 上单独启动 Python、Node、PostgreSQL 或 Redis。
4. 确认 `8080`、`8089`、`9090`、`3000`、`8000`、`5432`、`6379` 端口没有被其他程序占用。

项目由 Compose 启动 PostgreSQL、Redis、迁移任务、两个 API、两个预约 Worker、调度器、Nginx、Locust、Prometheus 和 Grafana。PostgreSQL 与 Redis 数据保存在 Docker 卷中，普通重启不会清空预约。

### 2.2 `.env` 文件

项目根目录的 `.env.example` 是本地示例配置。**仅在 `.env` 不存在时复制**：

```powershell
cd C:\Code\Python\CampusReserve
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Compose 即使没有 `.env` 也提供本地默认值；答辩时保留已经可用的 `.env`，不要临时覆盖。需要检查的主要配置：

| 配置 | 作用 | 答辩建议 |
|---|---|---|
| `POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD` | PostgreSQL 数据库及账号 | 保持现有值；如修改密码，`POSTGRES_DSN` 必须同步修改 |
| `POSTGRES_DSN` | API、Worker、迁移任务访问数据库 | Compose 内数据库主机名为 `postgres` |
| `REDIS_URL` | Redis 连接 | Compose 内 Redis 主机名为 `redis` |
| `JWT_SECRET` | 登录令牌签名 | 本地演示可使用现有配置；对外部署必须改成随机密钥 |
| `BOOKING_RESULT_TTL_SECONDS` | Redis 预约请求结果保留时间 | 默认 604800 秒，即 7 天 |

在已经初始化的数据卷上，仅修改 `.env` 中的数据库密码不会自动修改 PostgreSQL 内已有账号的密码。答辩当天不要为了排查问题直接删除数据卷。

## 3. 启动和检查

### 3.1 首次启动或代码更新后

先确认 Docker Desktop 显示正在运行，再执行：

```powershell
cd C:\Code\Python\CampusReserve
docker compose up -d --build
docker compose ps -a
```

第一次构建可能需要几分钟。正常情况下，`api-1`、`api-2`、两个 `booking-worker`、`scheduler`、`nginx`、`postgres`、`redis` 等服务会运行；一次性的 `migrate` 显示 `Exited (0)` 是成功完成迁移。

平时只需恢复已构建的项目时，可以执行：

```powershell
cd C:\Code\Python\CampusReserve
docker compose up -d
```

检查 API 和页面：

```powershell
Invoke-RestMethod http://localhost:8080/api/v1/system/health
Invoke-WebRequest http://localhost:8080/ -UseBasicParsing | Select-Object StatusCode
```

健康接口应返回 `status: ok`，页面状态码应为 `200`。随后打开 <http://localhost:8080/>。

### 3.2 本地入口与账号

| 用户名 | 密码 | 用途 |
|---|---|---|
| `student001` | `Student@123` | 学生预约演示 |
| `student002` | `Student@123` | 第二位学生、备用演示账号 |
| `venue_admin` | `Admin@123` | 场馆运营、预约查询和签到 |
| `platform_admin` | `Admin@123` | 平台管理、开放模板维护 |

同一个 <http://localhost:8080/> 登录页会按用户角色进入学生端或管理端。JWT 默认 30 分钟过期，过期后重新登录即可。

## 4. 功能演示步骤

### 4.1 学生预约：建议现场操作

1. 用 `student001` 登录。说明系统固定 1 个场馆、15 片场地，每天 08:00—22:00，每片场地按小时生成 14 个时段，正常全天共 210 个场地时段。
2. 页面可切换“今天”和“明天”，默认显示明天。每天 08:00 放出明天的库存；今天尚未开始且空闲的时段也能预约。
3. 切到“今天”说明状态：已开始且被预约的时段为“已预约”，其他已开始的时段为“已过期”，未开始且空闲的时段为“可预约”。若当天已接近闭馆，改用明天演示提交。
4. 在“明天”选择一个可用时段；如需展示并行场地规则，可在**同一时间选择两片不同场地**。点击“确认预约”。
5. 展示“预约请求记录”的 `PROCESSING` 到 `CONFIRMED` 状态，以及“我的预约”中的预约编号、使用日期、场地和时间。若查询暂时超时，可用请求记录里的“继续查询”恢复结果。

规则口径：每名学生每个使用日期最多确认 **2 个场地时段**。同一时间的两片不同场地计为 2 个时段；同一片场地的同一时段不能卖给两人。预约确认后不支持学生取消。

**演示前检查：**两个示例学生各只有每天 2 个时段额度。正式答辩前不要把需要演示的账号和日期全部订满；若 `student001` 已用完，换 `student002` 或展示已有预约，不要清空数据库卷。

### 4.2 管理员闭环：可选操作

1. 退出学生账号，用 `venue_admin` 登录。
2. 在“总览”查看最近放号批次；在“库存与放号”查看今日、明日批次及状态。
3. 在“预约与签到”输入刚才的预约编号查询，展示学生、使用日期和场地。需要展示现场签到时点击“签到”；该操作会改变预约状态。
4. 在“审计日志”查看管理员操作记录。
5. 可用 `platform_admin` 登录“开放规则”，说明模板为 08:00—22:00、60 分钟时段、提前 1 天 08:00 放号。

“暂停”“关闭”批次和修改场馆状态会影响学生预约，现场演示通常只查看，不要随意操作正在使用的批次。

### 4.3 讲解预约链路时可说

> 学生提交后，API 先调用 Redis Lua 原子检查库存、每日额度和请求编号；成功后把事件写入 Redis Streams，并立即返回请求编号。两个 Worker 异步消费事件，在 PostgreSQL 事务中再次核对额度和库存，最终写入预约。前端按请求编号查询最终结果。数据库的库存唯一约束是防止超卖的最后一道防线。

## 5. 压测和并发正确性演示

### 5.1 Locust 页面：展示请求速率、延迟和失败率

确保服务已启动，打开 <http://localhost:8089/>。Locust 在 Compose 容器内运行，目标 Host 已配置为 **`http://nginx`**；这是容器内部地址，不要填 `http://localhost:8080`。

建议先做一轮可控演示：

1. Number of users 填 **20**。
2. Spawn rate（或 Ramp up）填 **5 用户/秒**。
3. 点击 **Start**，运行约 30 秒。
4. 在 **Stats** 看请求数、RPS、平均响应时间和失败数；在 **Charts** 看曲线，在 **Failures** 看失败详情。
5. 点击 **Stop**，记录当次截图与参数。数值随电脑性能而变化，不必和示例数字一致。

当前 `tests/load/locustfile.py` **只压 `/api/v1/system/health/live` 健康检查接口**。这可以展示 Locust、Nginx、双 API 的请求处理和指标采集，**不能称为预约接口达到 5,000 RPS，也不能单独证明零超卖**。在答辩中主动说明这个范围。

不方便使用网页时，可在 PowerShell 运行同等的命令行演示：

```powershell
docker compose exec -T locust locust -f tests/load/locustfile.py --headless -u 20 -r 5 -t 30s --host http://nginx --only-summary
```

运行结束后，终端会打印请求总数、失败数、RPS 和响应时间分位数。不要在普通笔记本上直接输入 10,000 用户或声称已达到 5,000 RPS；这两项目前是项目目标，尚缺预约链路专项压测报告。

### 5.2 并发防超卖测试：展示正确性

Locust 演示之后，在项目根目录运行：

```powershell
docker compose exec -T api-1 pytest -q tests/integration/test_redis_atomic_reservation.py tests/integration/test_sync_booking.py -k concurrent
```

看到 `3 passed`（或 `... [100%]`）即可解释：测试并发争抢同一库存，以及同一学生并发请求时每日额度不能超过 2。它证明代码中的并发规则在测试场景下成立，但不等于 5,000 RPS 的容量成绩。

若老师问“预约接口是否真的跑通”，可以再展示学生端完整预约和以下端到端测试：

```powershell
docker compose exec -T api-1 pytest -q tests/integration/test_async_booking_api.py
```

### 5.3 Prometheus / Grafana：可选指标演示

打开 <http://localhost:9090/>，在查询框执行：

```promql
up{job="campus-reserve-api"}
```

正常时两个 API 目标的值均为 `1`。Locust 运行期间，可查询健康检查请求速率：

```promql
sum(rate(campus_reserve_http_requests_total{route="/health/live"}[1m]))
```

该指标来自 API `/metrics`，Prometheus 每 5 秒抓取一次。Grafana 地址是 <http://localhost:3000/>，本地默认账号和密码都是 `admin`，已配置 Prometheus 数据源；项目没有预置完整仪表盘，现场优先展示 Locust Charts 或 Prometheus 查询。

## 6. 常见问题与恢复

| 现象 | 操作 |
|---|---|
| `docker compose` 提示无法连接 Docker | 启动 Docker Desktop，等其显示运行后重试 |
| `8080` 页面无法打开 | 运行 `docker compose ps -a`，查看 `nginx`、`api-1`、`api-2` 是否运行；再执行 `docker compose logs --tail 80 nginx api-1 api-2` |
| 页面仍是旧版本 | 浏览器按 `Ctrl+F5` 强制刷新；如代码刚更新，执行 `docker compose up -d --build --no-deps nginx` |
| 登录失败 | 核对账号密码；检查 `docker compose logs --tail 80 api-1`，不要直接重置数据库 |
| 库存暂不可用或没有批次 | 等约 30 秒后刷新；检查 `docker compose logs --tail 80 scheduler` 和 `docker compose ps -a` |
| 今天没有可预约时段 | 今天已开始或被订满的时段不能再次预约，切换“明天”演示 |
| 预约一直显示处理中 | 在“预约请求记录”点击“继续查询”；检查 `docker compose logs --tail 80 booking-worker-1 booking-worker-2` |
| Locust 没有请求或大量失败 | 检查目标 Host 是否为 `http://nginx`、`nginx` 是否健康，再从 10～20 用户低负载重试 |
| 端口被占用 | 先关闭占用 `8080`、`8089` 等端口的其他服务，再启动 Compose |

现场查看实时日志：

```powershell
docker compose logs -f api-1 api-2 booking-worker-1 booking-worker-2 scheduler
```

按 `Ctrl+C` 只退出日志查看，不会停止容器。答辩结束后如需关闭服务并保留数据库：

```powershell
docker compose down
```

不要在保留演示数据的环境运行 `docker compose down -v`；`-v` 会删除 PostgreSQL、Redis 和监控数据卷。

## 7. 两分钟讲解词

> 这是一个校园羽毛球场预约系统。学生可以看今天和明天的库存，今天只允许预约尚未开始的空闲时段；每天 08:00 开放明天的场地。每人每天最多两个场地时段，也允许同一时间预约两片不同场地。提交后通过 Redis Lua 原子占位，Worker 异步落库，最终由 PostgreSQL 约束保证同一库存不被重复确认。管理端负责放号批次、预约查询和现场签到。我用 Locust 展示当前健康检查接口的请求速率、延迟与失败率，再用并发集成测试展示库存和每日额度不会被并发请求突破。5,000 RPS 是后续预约链路专项压测目标，不把当前健康检查结果冒充容量结论。
